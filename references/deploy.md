# 部署：把网站变成一个公开链接

`site/` 文件夹是纯静态网站，不需要构建、不需要服务器，任何静态托管平台都能用。这份文件帮你选平台，并一步步带用户完成部署。

平台的界面和规则经常变。下面的按钮名称以写作时（2026 年 10 月）各平台官方文档为准；和用户看到的不一致时，按用户屏幕上的实际情况引导，意思相近的按钮就是对的。

## 1. 先问清楚：谁要打开这个链接

部署前问用户一个问题：

> 这个网站主要给谁看？只需要德国或欧洲的 HR 能打开，还是也要让国内的人（家人、中资企业）能打开？

| 回答 | 建议 |
|---|---|
| 只要德国或欧洲能打开 | EdgeOne Pages、Netlify、Cloudflare Pages 都可以，用平台给的默认链接就行，不需要买域名 |
| 国内也要能稳定打开 | 需要**自己的域名**（见第 8 节）。各平台的默认链接在国内都不稳定：`*.vercel.app` 基本打不开；EdgeOne Pages 的默认域名在中国大陆受限，只能用 3 小时内有效的预览链接访问 |

不要承诺"国内一定能打开"。部署后请国内的人实际打开试一次（第 9 节）。

## 2. 部署前检查

- [ ] `site/` 文件夹的**最外层**直接就是 `index.html`，不是 `site/site/index.html`
- [ ] `site/` 里没有标为不公开的文件（工作证明原件、成绩单、在读证明等）
- [ ] 文件名只用英文字母、数字、连字符，没有空格和中文（有些平台对中文文件名支持不好）
- [ ] 打开 `site/index.html` 检查过一遍，阶段 8 的自检都通过
- [ ] `index.html` 里的标题、描述、分享预览标签已经改成用户的内容

## 3. 账号和登录

- **注册和登录由用户自己完成。** 不要替用户输入密码、验证码，也不要替用户点"同意条款"。需要登录时，告诉用户"请在打开的页面里登录，登录好了告诉我"。
- 如果当前环境可以操作浏览器，用户登录之后，可以由你完成上传等操作，但每一步之前说清楚要点什么。
- 推荐用户用常用邮箱注册，或用 GitHub 账号登录，方便以后找回。

## 4. 方式 A：EdgeOne Pages（首选）

腾讯云的静态托管平台，国际站地址 `pages.edgeone.ai`。不需要命令行，把文件夹拖进去就能部署。

### 首次部署

1. 用户打开 EdgeOne Pages 国际站控制台，注册并登录。
2. 点 **Create Project**（创建项目），选择 **Direct Upload**（直接上传）。
3. 填 **Project Name**（项目名），建议用姓名，例如 `xiao-lin`。
4. 选择 **Acceleration Region**（加速区域）：
   - 选**全球可用区（不含中国大陆）**：绑定自定义域名时**不需要 ICP 备案**。留学生一般选这个。
   - 含中国大陆的选项：国内访问更快，但绑定自定义域名必须先做 ICP 备案，留学生通常办不了。
5. 把 `site/` 文件夹（或者把它压缩成的 zip）拖进上传区域。支持一个文件夹、一个 zip 或一个 HTML 文件；单个文件不超过 25 MB。
6. 点 **Start Deployment**（开始部署），等待完成，复制项目链接。

### 如果当前环境接入了 EdgeOne Pages MCP

EdgeOne 官方提供 MCP 工具（例如部署文件夹或 zip 的工具），调用后直接返回公开链接。环境里有这个工具时，可以用它部署 `site/` 文件夹，省去手动上传。部署完成后，同样要做第 9 节的检查。

### 关于国内访问

EdgeOne 的官方文档说明：在中国大陆，项目的默认域名受限，只能通过控制台生成的预览链接访问，**预览链接 3 小时后失效**。所以要让国内稳定访问，必须绑定自己的域名（第 8 节）。

## 5. 方式 B：Netlify

1. 用户在 `netlify.com` 注册并登录（**一定要先登录**：不登录直接用 Netlify Drop 上传的网站会在短时间后过期，而且会被加上密码保护，没法发给别人）。
2. 打开 Netlify Drop 页面（`app.netlify.com/drop`），把 `site/` 文件夹拖进去。
3. 部署完成后得到一个 `随机名称.netlify.app` 的链接。在站点设置里可以把名称改成好记的，例如 `xiao-lin.netlify.app`。

国内访问：时好时坏，不建议作为国内访问的方案。

## 6. 方式 C：Cloudflare Pages

1. 用户在 `cloudflare.com` 注册并登录。
2. 进入控制台的 **Workers & Pages**，选择创建一个 **Pages** 项目，选**直接上传**（Upload assets）。
3. 填项目名，把 `site/` 文件夹拖进去，部署。
4. 得到 `项目名.pages.dev` 的链接。

国内访问：`pages.dev` 在国内不稳定。

## 7. 方式 D：GitHub Pages（进阶）

适合本来就用 GitHub、想把代码也公开的用户（技术岗有加分）。

1. 用户在 GitHub 新建一个公开仓库。如果仓库名是 `用户名.github.io`，网址就是 `https://用户名.github.io`。
2. 在仓库页面选择上传文件，把 `site/` **里面的**所有文件和文件夹拖进去（不是拖 `site` 文件夹本身），提交。
3. 进入仓库的 **Settings → Pages**，来源选 main 分支、根目录，保存。
4. 等一两分钟，网址就生效了。

注意：公开仓库里的所有文件任何人都能看到，所以不公开的文件绝对不能放进去。国内访问 `github.io` 也不稳定。

## 8. 自定义域名

**什么时候需要**：要让国内稳定访问；或者想要一个更专业、更好记的网址（例如 `xiaolin.de`、`xiaolin.com`）。

**怎么做**：

1. 用户在任意域名注册商买一个域名。常见的 `.com`、`.de` 每年费用大约在几欧元到十几欧元之间，以注册商的实际价格为准。
2. 在部署平台的项目设置里找到 **Custom Domain**（自定义域名），添加这个域名。
3. 平台会给出一条或几条 DNS 记录（通常是 CNAME）。用户到域名注册商的 DNS 设置里添加这些记录。
4. 等待生效（几分钟到几小时），平台会自动配置 HTTPS。

**备案**：域名解析到**中国大陆以外**的节点时，不需要 ICP 备案。用 EdgeOne Pages 时，选"全球可用区（不含中国大陆）"即可。

域名买好以后，以后换平台也不用换链接。

## 9. 部署后检查

- [ ] 用手机打开链接，首页、一个故事页、速览页都看一遍
- [ ] 切换每种语言看一遍
- [ ] 点开一张图片、一个文件，确认能正常打开
- [ ] 把链接发到自己的邮箱或 LinkedIn 私信里，看分享预览显示的标题和描述对不对
- [ ] 如果需要国内访问：请国内的家人或朋友用手机流量打开一次，确认能打开
- [ ] 直接访问一个不公开文件可能的路径（例如 `链接/assets/docs/transcript.pdf`），确认打不开

## 10. 以后更新网站

1. 改 `site/` 里的内容（通常只改 `content.js` 和图片）。
2. 重新上传整个 `site/` 文件夹到**同一个项目**：
   - EdgeOne Pages：项目的 **Build & Deploy** 页面 → **New Deployment** → 拖入新文件夹
   - Netlify：项目的 **Deploys** 页面，把文件夹拖到上传区域
   - Cloudflare Pages：项目里创建新的部署，上传文件夹
   - GitHub Pages：在仓库里上传覆盖修改过的文件
3. 链接不变，几分钟内生效。

部署完成后告诉用户把链接放在：简历页眉、LinkedIn（精选栏和联系信息）、求职信签名、邮件签名。
