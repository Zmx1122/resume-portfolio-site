## 1. 网站给谁看

一个求职网站通常有三类读者，要求完全不同：

| 读者 | 看多久 | 想知道什么 | 网站怎么满足 |
|---|---|---|---|
| HR 初筛 | 30 秒左右 | 这个人是谁、找什么岗位、什么时候能来、会不会德语、有没有相关经历 | 首页第一屏 + "速览"页 |
| 用人部门负责人 | 几分钟 | 这个人真正做过什么、怎么做的、水平如何 | 精选故事和故事页 |
| 其他人（家人、朋友、校友） | 随意 | 大致了解 | 关于我、时间线 |

**设计时优先照顾前两类。** 首页第一屏回答 HR 的问题，精选故事让用人部门负责人愿意点进去看。

## 2. 页面类型

| 页面 | 内容 | 什么时候有 |
|---|---|---|
| 首页 | 定位语、快速信息、精选故事、联系方式；紧凑型布局下还包括所有其他版块 | 总是 |
| 故事页 | 一个故事的完整讲述，见第 6 节 | 每个故事一页 |
| 经历 | 工作、教育、获奖合在一条时间线上，最新的在前 | 总是（紧凑型里是首页的一个版块） |
| 技能 | 按类别分组的技能，每项技能显示它出现在哪些故事里；点开某项技能，列出相关故事 | 有技能数据时 |
| 证书与文件 | 语言能力、证书（附验证链接）、荣誉、文件墙 | 有证书或文件时 |
| 关于我 | 个人故事、兴趣、推荐语 | 有 `about` 或可显示的引用时 |
| 速览（Kurzprofil） | 一页纸的简历视图，可以直接打印或存成 PDF | 总是 |

没有内容的页面不出现在导航里，也不生成空页面。

## 3. 两种布局：紧凑型和编辑型

内容少的人做成多页网站，每页都空荡荡的；内容多的人挤在一页，又长又乱。所以按内容量选布局，写在 `meta.layout` 里：

| 布局 | 适合 | 结构 |
|---|---|---|
| `compact`（紧凑型） | 故事少于 4 个，比如在读学生、刚毕业 | 一个长首页，所有版块从上往下排；导航点击后滚动到对应版块。故事仍然有自己的页面 |
| `editorial`（编辑型） | 故事 4 个或以上，经历比较丰富 | 首页只放定位、精选故事和简短时间线；经历、技能、证书与文件、关于我各自一页 |

不写 `meta.layout` 时，模板按故事数量自动选。用户明确偏好时以用户为准。

### 紧凑型的导航树

```
首页（一个长页面）
├── 第一屏：头像、姓名、定位语、快速信息、按钮（联系 / 下载简历 / 速览）
├── 精选故事 ────────→ 故事页
├── 经历（时间线）──→ 有故事的条目链接到故事页
├── 技能 ───────────→ 技能筛选（列出相关故事）
├── 证书与文件
├── 关于我
└── 联系
速览（单独一页，可打印）
```

### 编辑型的导航树

```
首页
├── 第一屏：头像、姓名、定位语、快速信息、按钮
├── 精选故事 ────────→ 故事页
├── 其他故事（标题列表）
├── 简短时间线 ──────→ 经历页
└── 联系
经历页 ──────────────→ 故事页
技能页 → 技能筛选 ───→ 故事页
证书与文件页
关于我页
速览页（可打印）
```

ylkhayat.vercel.app 是编辑型的一个好例子：首页像报纸头版，故事按公司分组，技能页统计每项技能出现在几个故事里。

## 4. 网址规则

网站只有一个 `index.html`，页面用 `#` 后面的路径区分。每个网址都带语言，这样用户可以把某种语言的某个页面直接发给别人：

| 网址 | 页面 |
|---|---|
| `#/de/` | 德语首页 |
| `#/de/story/muster-dashboard` | 德语的某个故事页 |
| `#/en/experience` | 英语的经历页（紧凑型里滚动到首页的经历版块） |
| `#/en/skills` | 技能页 |
| `#/en/skills/power-bi` | 筛选出用到 Power BI 的故事 |
| `#/zh/documents` | 证书与文件页 |
| `#/zh/about` | 关于我 |
| `#/de/cv` | 速览 |

没有 `#` 的网址打开默认语言的首页。切换语言时停留在同一个页面，只换语言。

## 5. 首页的顺序

第一屏（不滚动就能看到的部分）必须包含：

1. 姓名
2. 定位语：一到两句，说清"我是谁、能做什么"，要和求职方向对应
3. 快速信息：所在城市、可工作时间、语言（例如"Deutsch C1 · English C1"）
4. 一个主要按钮：联系，或者下载简历

第一屏之后的顺序按用户情况调整：

| 用户情况 | 建议顺序 |
|---|---|
| 有相关工作或实习经历 | 精选故事 → 经历 → 技能 → 证书与文件 → 关于我 |
| 在读、经历少、论文或项目强 | 精选故事（论文和项目）→ 教育 → 技能 → 证书与文件 → 经历 → 关于我 |
| 转行 | 精选故事（和新方向相关的放前面）→ 技能 → 经历 → 关于我（讲清楚为什么转） |
| 科研方向 | 研究和论文 → 发表 → 教育 → 经历 → 关于我 |

模板默认按第一行的顺序排。紧凑型布局需要调整时，在 `meta.sections` 里写版块顺序，例如 `["stories", "education", "skills", "documents", "experience", "about"]`（写了 `"education"`，教育会从经历里单独拿出来）。编辑型布局的首页固定为第一屏、精选故事、简短时间线和联系，其他版块各自成页。

## 6. 故事页的结构

从上到下：

1. **返回链接**：回到上一级，例如"← 经历"
2. **栏目标签**：所属的公司、学校或项目，加类型（例如"Muster GmbH · Werkstudent"）
3. **标题**：用问题或结果起标题
4. **导语**：一句话
5. **信息行**：角色 · 时间
6. **关键数字**：最多 3 个
7. **主图**（如果有），带说明文字
8. **问题**：背景和要解决的问题
9. **我做了什么**：2–5 条
10. **结果**
11. **更多图片**：点击放大，带说明
12. **引用**：工作证明摘录或推荐语
13. **证据**：相关证书和文件，点开看摘要或原件
14. **技能标签**：点击跳到技能筛选
15. **上一个 / 下一个故事**

没有的部分直接省略，不显示空标题。

## 7. 交叉链接

网站的专业感很大程度来自"处处有据可查"。这些链接由模板根据 `content.js` 里的 id 自动生成：

- 经历条目 → 它的故事
- 故事 → 所属经历，以及同一经历下的其他故事
- 故事的技能标签 → 技能筛选页 → 所有用到这项技能的故事
- 故事的证据 → 文件详情（公开文件可以直接打开）
- 语言能力 → 对应的语言证书
- 荣誉 → 对应的故事和证书

## 8. 文字长度

| 内容 | 建议长度 | 原因 |
|---|---|---|
| 定位语 | 1–2 句，中文 50 字以内，德语和英语 25 词以内 | 第一屏要一眼读完 |
| 故事标题 | 中文 25 字以内，德语和英语 70 个字符以内 | 卡片上不换超过两行 |
| 故事导语 | 1 句 | 卡片上显示 |
| 问题、结果 | 各 1–3 句 | |
| 我做了什么 | 2–5 条，每条 1 句 | |
| 经历要点 | 每段经历 2–4 条 | 详细内容放进故事 |
| 关于我 | 2–3 段，每段 2–3 句 | |
| 图片说明 | 1 句 | |

德语通常比英语长 20–30%，比中文长得多。按德语长度检查卡片和按钮会不会撑破。
